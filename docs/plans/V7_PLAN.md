# V7 ZIP 导出与导入计划

状态：规划中（2026-11-13）。尚未实现，当前代码行为不变。ZIP 导出、ZIP 导入和音频关联规则见下文；待确认项在实现前处理。

## 1. 范围

### 1.1 ZIP 导出

- 在现有“导出”菜单的“文本 .txt”“JSON .json”之外增加 ZIP 导出。
- ZIP 内固定三个文件：
  1. 与 ZIP 同名的 `.txt`；
  2. 与 ZIP 同名的 `.json`；
  3. 当前 `activeSha` 对应的音频文件，条目名使用与 ZIP 相同的基名和原扩展名，例如 `song.wav`；原始文件名仍保存在 JSON 的 `music.audios[sha].name` 中。这样导出的 ZIP 可以直接按同一套规则重新导入。
- 只包含当前正在关联的音频。`music.audios`、`music.alignments`、TXT/JSON 中记录的其他历史 SHA 一律不打包。
- TXT/JSON 的内容保持现有导出行为，仍可包含历史 SHA 记录；ZIP 只是不包含那些历史音频。
- 没有当前音频、音频文件缺失或无法读取时，不生成只有两个文件的 ZIP；禁用入口或明确报错。

### 1.2 ZIP 导入

- ZIP 根目录下按 ZIP 文件名寻找三个文件：
  - `song.zip` → `song.txt`、`song.json`、`song.wav` 或 `song.mp3`。
- 只读取根目录条目，忽略子目录、目录条目和与 ZIP 名称不匹配的文件。
- 序列来源优先级：
  1. JSON 存在且通过现有 `parseJson`/`validate`：采用 JSON。
  2. JSON 缺失、语法错误、版本/结构校验失败：回退 TXT。
  3. TXT 也缺失或解析失败：弹出“节拍器序列读取错误”。
- 采用 JSON 时不与 TXT 合并；采用 TXT 时标题使用 ZIP 文件名去掉 `.zip`。
- 音频可选：
  - 没有音频文件：正常导入序列，不关联音频。
  - 有音频：计算原始字节 SHA-256，与所选序列中的 SHA 集合比较。
  - 匹配：把音频作为该 SHA 的音频关联，设为当前音频，并沿用已有对齐。
  - 不匹配：不关联音频，仍导入序列。
- 音频文件存在但解码失败，或 SHA 匹配但字节无法解码时，不能当作有效关联；具体提示见待确认项。

## 2. 序列的 SHA 集合

### 2.1 JSON 来源

从以下位置取并集：

- `music.audios` 的键；
- `music.alignments` 的键；
- `activeSha`（如果存在且合法）。

### 2.2 TXT 来源

- 所有 `Alignment:{SHA:...}` 行中的 SHA。
- TXT 不含音频元数据；匹配后按现有流程补上音频引用。

### 2.3 匹配规则

- 只比较完整 64 位小写十六进制 SHA，不做前缀或文件名匹配。
- 同一 SHA 只关联一次。
- 匹配的 SHA 成为 `activeSha`；`activateAudio` 恢复该 SHA 的预备节拍快照并更新第一段 BPM，行为与现有“选择音频”一致。
- 如果一个音频同时匹配多个条目（正常不会发生），按同一 SHA 处理。

## 3. 实现方式

### 3.1 ZIP 库

建议引入 `fflate`（MIT）同时处理 ZIP 导出和导入：

- 支持 STORE/DEFLATE、CRC32、UTF-8 文件名；
- 避免手写 EOCD、中央目录、deflate 和 CRC；
- 导入需要读取常规 ZIP，手写解析的成本和风险明显高于导出。

如不引入依赖，导出可以手写 STORE ZIP，但导入会复杂很多；默认建议用库。引入时更新 `pnpm-lock.yaml` 和 `docs/THIRD_PARTY_NOTICES.md`。

### 3.2 导出流程

1. 取当前 `activeSha` 和 `music.audios[activeSha]` 的显示信息。
2. 从 `useMusic` 的内存文件或 IndexedDB `readAudio(sha)` 取得音频 Blob。
3. 生成 TXT、JSON 文本。
4. 用同一基名生成三个 ZIP 条目；音频使用原扩展名并清理路径分隔符和 Windows 非法字符，原始文件名只保存在 JSON 元数据中。
5. 下载 `<曲名>.zip`，并释放临时 URL。

### 3.3 导入流程

1. 文件选择器增加 `.zip,application/zip`；现有 TXT/JSON 导入保持不变。
2. 读取 ZIP 字节，解压到内存；校验 ZIP 大小、解压后大小和条目数量。
3. 按根目录、基名筛选 txt、json 和音频条目。
4. 按第 1.2 节选择 JSON/TXT，得到 `Song`。
5. 新建标签并切换到该标签。
6. 若存在音频：计算 SHA，取所选序列的 SHA 集合；匹配则写入音频引用和 `activeSha`，并让音频立即可播放（IndexedDB 或 `useMusic` 内存文件）。
7. 两者都读取失败时，弹出“节拍器序列读取错误”；不创建空标签。

## 4. 边界与错误处理

- ZIP 文件名与内部文件名按“同基名”匹配；大小写策略待确认，默认建议不区分 `.txt`/`.json` 扩展名的大小写。
- 音频只接受 `.wav`/`.mp3`，与现有音频选择范围一致；其他扩展名视为没有音频。若希望按内容解码尝试，需要另行确认。
- 若存在多个候选音频文件，默认取第一个符合 `.wav`/`.mp3` 的根目录条目；其余忽略。
- 音频没有 SHA 匹配时不报错、不关联；序列照常导入。
- 音频 SHA 匹配但解码失败时，建议报告“音频文件无法读取”，不把损坏字节写入 IndexedDB。
- ZIP 中的 TXT/JSON 解压后仍受现有 2 MiB 文本限制；ZIP 和音频需要单独的更大上限，建议初值：
  - ZIP 文件 ≤ 200 MiB；
  - 解压后总量 ≤ 300 MiB；
  - 条目数 ≤ 32。
- ZIP 条目名必须拒绝绝对路径和 `..` 路径；只读根目录，不写文件系统。
- 空 ZIP、只有音频没有序列、压缩包损坏、加密 ZIP 都按读取失败处理。
- 大音频打包/解压会产生内存副本；当前先按普通实现，超限时报告，不承诺任意大小。

## 5. 界面

- 导出菜单增加“ZIP .zip”，位于现有 TXT/JSON 之后。
- 无当前音频时禁用 ZIP 导出；音频缺失或读取失败时报告原因，不下载不完整 ZIP。
- 导入继续使用现有“导入”按钮和文件选择器；选择 `.zip` 时走 ZIP 流程。
- ZIP 导入可能需要数秒；期间禁用重复导入并显示现有消息/状态，不新增常驻说明。
- ZIP 读取失败统一使用“节拍器序列读取错误”；音频读取失败使用单独的音频错误提示。
- 文件名、ZIP 内条目名和音频名都要清理 Windows 非法字符。

## 6. 测试计划

单元：

- ZIP 条目名匹配：同基名、根目录、大小写、子目录、多个音频候选。
- JSON 优先：JSON 有效时不读 TXT；JSON 缺失/语法错误/校验失败时读 TXT。
- 两者都失败时返回统一错误。
- SHA 集合来自 `audios`、`alignments`、`activeSha`，以及 TXT 的 Alignment 行。
- 音频 SHA 匹配/不匹配、匹配 `alignments` 但不在 `audios`、解码失败。
- ZIP 大小、解压后大小、条目数、绝对路径和 `..` 的拒绝。
- 导出 ZIP 只含三个文件，TXT/JSON 内容与现有导出一致，音频只取 `activeSha`。

浏览器回归：

- 导出 ZIP，解压后检查三个文件名和内容；历史 SHA 音频不出现。
- 导入 JSON 优先的 ZIP，显示新曲目并正确关联音频。
- JSON 损坏时导入 TXT；两者都损坏时显示“节拍器序列读取错误”且不创建标签。
- 音频缺失、SHA 不匹配、音频损坏三种情况。
- 文件名含中文、空格和 Windows 非法字符。
- 大文件上限和拒绝路径。

人工：

- Windows 资源管理器解压中文文件名的 ZIP。
- 含 WAV 和 MP3 的 ZIP 导入后播放、对齐、保存和刷新恢复。
- 音频缺失/不匹配时确认曲目仍可编辑，不出现空白标签或误关联。

## 7. 待确认项

1. ZIP 库：采用 `fflate`，还是手写？建议 `fflate`。
2. ZIP 文件名与内部文件名大小写是否严格一致；默认建议扩展名不区分大小写。
3. 音频扩展名只认 `.wav`/`.mp3`，还是对任意扩展名尝试解码。
4. 多个候选音频时的选择规则；默认取第一个。
5. 音频 SHA 匹配但解码失败时：仅提示并不关联，还是同时保留音频引用以便用户替换。
6. 音频存在但不匹配任何 SHA 时，是否给用户一条“已导入序列，未关联音频”的提示；默认静默。
7. 无当前音频时 ZIP 导出是禁用还是点击后报错。
8. ZIP 大小、解压后大小和条目数上限是否采用第 4 节的初值。
9. TXT/JSON 是否继续包含历史 SHA；按当前需求保持现有内容，只限制 ZIP 中的音频。
10. ZIP 导出时音频条目是否统一命名为 `<zipbase>.<ext>` 以匹配导入规则；建议是，原文件名保留在 JSON 元数据中。

## 8. 不在 V7 范围

- 不打包历史音频、多个音频或 `audios` 中未激活的文件。
- 不实现目录结构、多个序列、封面或额外元数据。
- 不实现 ZIP 加密、分卷 ZIP 或流式大文件解压。
- 不改变现有 TXT/JSON 格式和音频 SHA 身份规则。
