# 网页节拍器 V3

面向 Windows 浏览器的纯前端节拍器，支持普通循环与变拍曲目序列。React + TypeScript + Vite，无需后端。音效已经随项目保存。

在线使用：[GitHub Pages](https://lightmain.github.io/sequence-metronome/)。

## 本地运行

建议使用 Node.js 24 LTS 和 pnpm 11.25；已在独立安装的 Node.js 24.22.2、pnpm 11.25.0 环境验证。依赖已安装时直接运行：

```powershell
cd E:\Casual\Metronome
pnpm.cmd dev
```

浏览器打开 http://127.0.0.1:5173/ 。固定地址和端口，以便使用同一份浏览器本地保存。首次获取项目时执行 `pnpm.cmd install --frozen-lockfile` 安装依赖。在 Windows PowerShell 中使用 `.cmd` 可以避免同名 PowerShell 脚本受执行策略限制；其他平台直接使用 `pnpm`。

## 功能

- 普通节拍器：拍号、BPM、首拍重音、总音量，持续循环。
- 序列节拍器：每段独立拍号与 BPM，指定开始小节，准备循环与准备一小节后进入。
- 显示整曲小节数、当前段内小节数、每拍圆角方形指示灯和当前段高亮。
- 在任意行间插入段落、删除、新增注释。
- 单击、Shift 连选、Ctrl 追加选择，以及拖动框选；支持多段、注释跨曲目复制粘贴。
- 每首曲目独立撤销与重做，最多保留 200 次编辑历史。
- 多曲目标签页，双击标签或 F2 重命名。
- 文本与 JSON 文件导入、导出；浏览器内直接编辑文本，解析失败给出行号与原因。
- Ctrl+S 保存当前曲目至浏览器，星号标记未保存修改，恢复已保存内容时清除星号。

## 速度与拍号

BPM 始终表示每分钟的四分音符数量。发声和拍灯以拍号分母对应的音符推进，每小节次数等于分子。

例如 BPM 120 时，4/4 每拍间隔 0.5 秒、每小节 2 秒；8/8 每拍间隔 0.25 秒、每小节同为 2 秒。

分子支持 1–32，分母支持 1/2/4/8/16/32，BPM 支持 20–400 且允许小数。第一拍以更高音调和音量提示；首版不提供分组重音。

## 快捷键

| 快捷键          | 操作                                                       |
| --------------- | ---------------------------------------------------------- |
| Enter           | 停止时直接播放                                             |
| Space           | 序列停止时进入准备循环；准备时在下一小节进入序列           |
| N               | 序列停止时先准备一小节；准备时在当前小节结束后再准备一小节 |
| M               | 准备时在当前小节结束后再准备两个完整小节                   |
| V               | 序列模式停止时打开文本编辑                                 |
| Backspace       | 取消播放                                                   |
| Ctrl+C / Ctrl+V | 复制选中行 / 在选定行间粘贴                                |
| Ctrl+A          | 选择当前曲目的全部行                                       |
| Delete          | 删除选中行                                                 |
| Ctrl+Z / Ctrl+Y | 撤销 / 重做                                                |
| Ctrl+S          | 保存当前曲目                                               |
| F2              | 重命名当前曲目                                             |

普通模式仅使用 Space 开始或停止，Enter、Backspace 不控制播放。序列进入“即将开始”后，Space、N、M、Enter 不再改变倒计时，Backspace 可取消。文字和数值输入框内保留正常编辑行为，Ctrl+S 可提交当前数值并保存。数值输入中 Enter 提交，Esc 取消。文本对话框需先点击确定再保存。

## 段落编号规则

第一段从 1 开始。非最后一段的终点由下一段起点推导；最后一段的终点可以直接修改。

悬停行间的“＋”并点击选择插入位置，再点击“新增段落”或按 Ctrl+V。未选择行间位置时，插入在所选行之后；未选择任何行时插入在曲尾。

新增段落默认一小节，继承上一演奏段落的拍号和 BPM。开头插入继承下一段；空曲目采用 4/4、120。注释不参与继承和小节计数。

插入只向后递推必要的起点。例如 `1–62 / 63 / 64–129` 在 63 小节段落前插入后成为 `1–62 / 63（新）/ 64 / 65–129`，曲尾仍为 129。连续单小节可能将递推传至曲尾，必要时延长曲目。

删除让后一段起点前移。例如删除 `1–62 / 63 / 64–129` 的中间段，结果为 `1–62 / 63–129`，后一段自己的拍号和 BPM 覆盖删除范围。

删除最后一段时缩短曲尾；删除全部演奏段落后保留空曲目，禁用播放。

## 文本格式

```text
1 4/4 120
#段落注释
63 2/4 120
64 4/4 120
130
```

每个演奏段落一行，字段为“起始小节 拍号 BPM”；`#` 开头为注释。最后的 130 是结束边界，表示实际播放到 129 小节。空曲目导出为结束边界 1，可保留注释。

支持 UTF-8、Windows/Unix 换行和空行。解析失败保留原曲目及文本草稿。导入打开新标签，文本文件名作为曲目名。JSON 格式包含格式版本、曲目名称、结束边界和段落/注释行，示例见 [开发计划](DEVELOPMENT_PLAN.md)。

## 本地保存

Ctrl+S 仅保存当前曲目，不提交其他曲目未保存的修改。关闭标签仅改变当前打开的工作区，已保存曲目仍保留在曲目库；点击“打开”可以重新打开。关闭前提示未保存修改。

已保存曲目可以跨刷新和浏览器重启恢复；未保存修改首版不自动恢复。星号通过与最近一次成功保存的内容比较得到，因此撤销回保存版本会自动清除星号。导出文件不改变星号。

保存限于当前浏览器及网站来源，本地服务和 GitHub Pages 不共享。清除网站数据也会删除保存，建议导出文本或 JSON 作为备份。无痕浏览的保存会随无痕窗口关闭而清除。

V3 读取旧版保存格式，在下次成功写入时迁移。标签只保存曲目标识，内容在曲目库中保存一份，另外保留最近一次被覆盖曲目的前一个保存版本。损坏的单首曲目会隔离并保留原始条目；存在有效恢复版本时自动恢复并提示。整个保存文档无法解析或属于未知版本时，拒绝覆盖。

同一曲目在两个网页编辑时，旧网页保存会报告冲突并保留星号。请先导出旧网页的修改，关闭该曲目标签，再通过“打开”读取最新版本。支持 Web Locks（浏览器提供的跨网页互斥锁）的浏览器会串行处理保存；缺少此功能时仍检查版本，但无法保证两个同时发生的写入互斥。曲目库仍受浏览器本地存储配额限制，超额保存会提示失败。

## 播放

准备模式始终使用曲目第一段的拍号与 BPM，即使正式播放的开始小节位于其他段。准备小节不占正式小节编号；正式播放从指定小节第一拍开始，到曲尾完整结束时停止。

序列播放时锁定结构和参数编辑，仍可调节音量、保存和导出。切换曲目或模式会停止播放。普通模式可以实时调速，拍号变化从下一小节开始。

使用浏览器音频时钟提前安排节拍，停止时取消已安排的声音和加载请求。启动超过 10 秒会报告超时。页面转入后台、音频设备中断或调度明显落后时停止并提示重新开始，回到页面后不会自行恢复。手机适配、锁屏播放、分组重音、暂停和循环练习留待后续版本。

## 检查与构建

```powershell
pnpm.cmd check
pnpm.cmd test:e2e
pnpm.cmd preview
```

构建产物位于 `dist/`。`pnpm preview` 在 http://127.0.0.1:4173/ 预览生产构建。

`pnpm check` 依次执行格式、ESLint 静态检查、TypeScript 类型检查、单元测试和生产构建。`pnpm format` 整理格式。浏览器测试使用 Playwright，即操作真实浏览器的自动化工具；Windows 默认使用已安装的 Chrome，Linux 首次运行需执行 `pnpm exec playwright install --with-deps chromium`。测试自行启动 4188 端口的生产预览，并使用项目子路径验证资源。

## GitHub Pages 发布

仓库为 [lightmain/sequence-metronome](https://github.com/lightmain/sequence-metronome)。在 Settings → Pages 中将 Source 设置为 GitHub Actions。提交到 `main` 后，工作流依次执行：

1. Windows 和 Linux 的 `pnpm check`，以及 Linux 浏览器回归测试。
2. 全部通过后，以仓库的 Pages 子路径构建并上传 `dist/`。
3. 使用 GitHub 官方发布操作部署到 `github-pages` 环境。拉取请求仅检查，Actions 页面也可手动运行。

工作流使用 Node.js 24、固定的 pnpm 版本和锁文件，第三方操作固定到提交。失败的浏览器测试保存截图和执行记录 7 天。无需部署 Node.js 服务，线上仅提供静态文件。可在 Actions 查看发布对应的提交；需要回退时恢复到旧代码再重新部署。V2 代码无法读取 V3 已迁移的保存格式，回退前应导出曲目。

## 目录

- `src/model.ts`：数据校验、段落算法与导入导出。
- `src/transport.ts`：音乐时间线与音频调度。
- `src/storage.ts`：撤销、重做与修改比较。
- `src/persistence.ts`：浏览器保存、迁移、冲突检查和恢复。
- `src/components/`：播放显示、段落列表、曲目标签与对话框。
- `src/hooks/`：选择行为、音频生命周期与稳定事件处理。
- `src/App.tsx`：协调曲目操作、文件、剪贴板与快捷键。
- `tests/`：数据、存储与音乐调度的单元测试。
- `e2e/`：浏览器交互回归测试。
- `.github/workflows/ci.yml`：跨平台检查及 Pages 发布。
- `public/sounds/`：节拍音效及许可。
- `examples/`：可直接导入的文本和 JSON 示例。

## 验证范围

单元测试覆盖段落编号、格式校验、保存和迁移、损坏恢复、多网页冲突、音乐时间线、倒计时边界、异步取消与资源释放。浏览器回归覆盖选择、框选、输入、快捷键、对话框、导入、复制粘贴、历史、保存刷新和倒计时。

V3 已通过 70 项单元测试、13 项浏览器回归、Windows/Linux 持续集成和 Pages 部署。2026-11-10 已在发布的 HTTPS 页面验证资源加载、浏览器音频启动与拍灯、两种播放模式、停止，以及保存后刷新恢复。

音频浏览器测试请求实际服务器中的 WAV，并使用浏览器解码；只模拟扬声器输出。受控浏览器对媒体请求可能返回空响应，测试通过 Playwright 请求同一服务器文件后交给浏览器。自动化结果不测量实体扬声器的声音和系统输出延迟。文件下载的浏览器验收尚未自动化，文本和 JSON 往返由单元测试覆盖。

输入文件及剪贴板上限为 2 MiB，每首曲目最多 10000 行，名称 1–200 字符，每条注释最多 20000 字符。

## V2 交互

- 上方为节拍显示，下方为状态和操作，按钮集中在右下角；普通模式不显示小节统计。
- 拍灯固定为 72 × 72px，每行最多 8 个，超出换行。
- 普通单击和框选替换选择，Ctrl 单击和框选取并集。Shift 单击选择起点至目标行，Ctrl+Shift 将该范围加入已有选择。Shift 框选替换选择，Ctrl+Shift 框选取并集。输入框单击只编辑。
- 点击列表外清除选择，Ctrl 点击列表外保留行选择；行间插入位置在列表外点击时始终清除。
- “列表滚动跟随播放”只滚动列表内部，保持上方节拍显示位置。
- 准备模式显示横杠。Space 进入时当前剩余小节显示 0；N 显示 -1→0；M 显示 -2→-1→0。就绪时 N 为一个完整的 0 小节。完整倒计时小节整体升调，当前剩余的不完整小节保持原音调。
- 倒计时确定后只保留“取消播放”，正式播放后显示“停止播放”。段内进度显示在当前段的“小节数”列。
- 文本编辑解析失败只显示下方红字，不弹出额外对话框。
